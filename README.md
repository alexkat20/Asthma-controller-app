# Peak Flow — веб-чат-бот для контроля астмы

Веб-приложение (FastAPI + чат-интерфейс в браузере, без Telegram), которое можно
открыть на телефоне или компьютере и пользоваться как обычным чатом.

## Возможности

1. **Профиль пользователя** — при первом обращении бот один раз проводит короткую
   анкету (пол, возраст, рост, вес, курение, город, аллергия на пыльцу — только на
   те растения, которые реально можем мониторить). Дальше не повторяется;
   посмотреть/обновить — командой «профиль» / «изменить профиль».
2. **Запись показаний — пошаговый мастер в 4 шага**: (1) три числа с пикфлоуметра,
   (2) препарат кнопками из справочника (или свой вариант), (3) количество
   принятых доз, (4) состояние — спорт/стресс/аллергия/болезнь/перелёт (кнопками
   или через запятую текстом, либо «Ничего из этого»). Раньше шага 4 не было, и
   состояние тихо терялось — теперь запрашивается явно.
3. Зоны (зелёная/жёлтая/красная) считаются по персональному рекорду в скользящем
   90-дневном окне, а не по последним N записям подряд.
4. Анализ и графики за неделю / 2 недели / месяц / квартал / год / **всё время** /
   произвольный диапазон дат (ДД.ММ.ГГГГ-ДД.ММ.ГГГГ).
5. Прогноз на сегодня и на неделю вперёд: тренд + сезонность по дню недели +
   эффект вчерашних состояний (спорт/стресс/аллергия/болезнь/перелёт).
6. При попадании в жёлтую/красную зону бот подбирает препарат на основе истории —
   какой препарат чаще ассоциировался с возвратом в зелёную зону на следующий
   день. Это статистика по вашим же данным, а не медицинская рекомендация — так
   и подписано в ответе.
7. Данные о пыльце/аллергенах через бесплатный Open-Meteo Air Quality API (без
   ключа, покрытие — Европа): команда «город Москва» задаёт регион, «аллергия» —
   проверка сейчас, а утренний дайджест включает сводку по пыльце вместе с
   прогнозом пикфлоу. Если в профиле указаны свои аллергены — именно они
   выделяются в сводке в первую очередь.
8. Импорт истории из CSV/Excel (кнопка загрузки в интерфейсе).
9. **Экспорт данных в CSV** — команда «экспорт» / «скачать данные» / «выгрузить»,
   период тот же список, что и у анализа (включая «всё время» и произвольный
   диапазон). В файле — показания, пороги зон, принятые препараты с дозами и
   состояние за каждый день. Формат колонок совпадает с тем, что ожидает импорт,
   поэтому экспортированный файл можно позже загрузить обратно.
10. Тест контроля астмы (ACT-подобный опросник) — ежемесячно, начиная с первого
    использования; отчёт для врача (HTML, печатается в PDF из браузера); семейный
    read-only доступ по ссылке.
11. Ежедневные напоминания и фоновые уведомления об ухудшении зоны (поллинг, без
    push-сервисов).

## База данных: SQLite или PostgreSQL

По умолчанию используется SQLite (файл `peak_flow.db` рядом с `main.py`) —
ничего настраивать не нужно. Чтобы использовать PostgreSQL, задайте переменные
окружения перед запуском:

```bash
# SQLite (по умолчанию)
uvicorn main:app --reload --port 8000

# PostgreSQL — отдельными переменными
DB_BACKEND=postgres \
POSTGRES_HOST=localhost \
POSTGRES_PORT=5432 \
POSTGRES_DB=peakflow \
POSTGRES_USER=peakflow \
POSTGRES_PASSWORD=secret \
uvicorn main:app --reload --port 8000

# PostgreSQL — готовой строкой подключения (приоритетнее отдельных переменных)
DB_BACKEND=postgres \
DATABASE_URL=postgresql+psycopg://user:pass@host:5432/db \
uvicorn main:app --reload --port 8000
```

Схема БД управляется через **Alembic**. Перед первым запуском на новой базе
(и после каждого обновления кода со схемой) выполните:

```bash
alembic upgrade head
```

Команда сама подхватывает `DB_BACKEND`/`DATABASE_URL` из окружения (см.
`alembic/env.py`) — не нужно отдельно настраивать URL для Alembic.

`main.py` при старте также вызывает `init_db()` — это создаёт таблицы "на
всякий случай" для быстрого локального старта, если вы забыли применить
миграцию, но полагаться на это в проде не стоит: `alembic upgrade head` —
единственный способ безопасно накатывать *изменения* схемы позже.

## Запуск

```bash
pip install -r requirements.txt
alembic upgrade head
uvicorn main:app --reload --port 8000
```

Открыть в браузере: http://localhost:8000

При первом открытии в браузере создаётся уникальный `user_id` (в `localStorage`),
поэтому несколько человек могут пользоваться одним и тем же запущенным сервером
независимо друг от друга.

## Структура проекта (слоями)

```
main.py                    — сборка FastAPI-приложения: роутеры, статика, планировщик
alembic/                    — миграции схемы БД (alembic upgrade head)
  env.py                     — URL берётся из repositories/db_engine.py (тот же DB_BACKEND)
  versions/                  — история миграций, начиная с initial schema
models/
  domain.py                 — доменные структуры (ZoneThresholds)
  schemas.py                 — Pydantic-схемы запросов/ответов API
repositories/                — весь SQL (через SQLAlchemy) и работа с БД
  db_engine.py                 — движок/сессии, выбор SQLite/PostgreSQL по DB_BACKEND
  orm_models.py                 — SQLAlchemy ORM-модели (источник схемы для Alembic)
  database.py                 — зоны, импорт файлов, CRUD показаний/препаратов
  profile_repository.py       — анкета пользователя (user_profile)
  settings_repository.py      — город (для пыльцы) и напоминания
  act_repository.py            — результаты теста контроля астмы
  family_repository.py         — read-only ссылки семейного доступа
services/                    — бизнес-логика
  nlp_service.py               — определение состояния по свободному тексту
  forecast_service.py          — прогноз на сегодня и неделю
  recommend_service.py         — подбор препарата на основе истории
  allergy_service.py           — клиент Open-Meteo (геокодинг + пыльца)
  analytics_service.py         — анализ за период, график (текст + картинки)
  export_service.py             — сборка CSV-экспорта за период
  logging_service.py           — пошаговый мастер записи (показания->препарат->доза->состояние)
  medicine_service.py          — добавление/обновление препарата
  profile_service.py           — онбординг анкеты (шаг за шагом, один раз)
  location_service.py          — город <-> координаты, проверка аллергии
  act_service.py                — тест контроля астмы
  report_service.py             — HTML-отчёт для врача
  family_service.py             — семейный read-only доступ
  reminder_service.py          — команда напоминания + фоновый планировщик дайджеста
  notification_service.py      — очередь уведомлений для поллинга фронтендом
  chat_service.py               — верхнеуровневый роутинг сообщений чата
endpoints/                    — тонкие HTTP-роутеры FastAPI (вызывают services)
  chat.py, upload.py, export.py, report.py, notifications.py
utils/                        — общие мелочи без побочных эффектов
  dates.py                     — периоды/диапазоны дат (границы считаются в Python —
                                  важно для переносимости между SQLite и PostgreSQL)
  formatting.py                — переводы (зоны/флаги/пол/курение), тексты, меню
  plotting.py                   — рендер matplotlib-графика в base64 data-URI
static/                        — фронтенд (HTML/CSS/JS, без фреймворков)
```
